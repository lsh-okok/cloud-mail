# 邮箱兑换码、订单与 TXT/ZIP 交付

日期：2026-11-16

状态：已在当前工作区实现并完成本地验证，尚未部署到生产服务器。业务基线见 [邮箱卡密管理与兑换方案](mailbox-cards-plan.md)。

## 1. 已交付行为

一个兑换码固定绑定一个本地/MX 主邮箱，每码最多成功核销一次。兑换码默认长期有效；子邮箱取码链接保留原有效期，核销、重新生成和重新下载均不为链接续期。

管理员可初次生成、复制、导出、手动停用、恢复未核销的停用码、重新生成，以及查看历史和兑换订单。已核销后也能为同一主邮箱生成新码，新码获得一次新的兑换机会，旧码永久作废；原订单和已交付链接继续按原规则使用。初次生成的重复请求返回已有当前码，不会自动换码或清除核销记录。

兑换覆盖该主邮箱 ID 下的所有现有子邮箱链接，不自动纳入同域名的其他主邮箱或未建立链接的邮件地址。同一子邮箱的不同平台链接分别交付；已经过期的链接仍保留在文件中，页面标注其有效期，打开时按原规则拒绝。没有任何子邮箱链接时失败且不核销；链接或平台配置不能完整、准确交付时明确失败，不静默漏项或截断。

单码成功交付一个 TXT；去重后提交两个及以上码按批量处理，每个成功主邮箱一个 TXT，统一打包为 ZIP。批量只有一个成功主邮箱时仍交付 ZIP。失败项显示在订单中，不生成空 TXT；全部失败也保留可查询的失败订单，不消耗任何码。

TXT 使用 UTF-8 BOM、CRLF，无表头，每行严格为：

```text
child@example.com----https://mail.example.com/m/exact-token
```

交付使用对应原链接的精确 Token URL，保留收件人及平台范围。ZIP 的文件名经过安全化并处理同名，条目为平铺的主邮箱 TXT，不允许目录穿越路径。ZIP32 由 Node.js 24 的原生 DEFLATE、CRC32 和有界封装生成，无新增第三方运行依赖。

## 2. 页面入口与使用

| 入口 | 使用者 | 功能 |
| --- | --- | --- |
| `/admin/cards` | 站点管理员 | 兑换码分页、邮箱/完整码搜索、状态统计、当前页批量初次生成与导出、停用/恢复、重新生成、历史和订单 |
| `/redeem` | 匿名持码人 | 粘贴或追加 TXT、准备并保存查询凭证、单码/批量兑换、逐项结果、下载 TXT/ZIP、失败码重试 |
| `/orders` | 持有订单查询凭证的人 | 凭查询凭证查单、导入已保存的凭证 TXT、重复下载原交付文件；订单号选填 |

公开页面使用独立匿名客户端，即使浏览器存在过期管理员令牌，也不会被管理员初始化重定向到登录页，不发送管理员 Authorization。凭证、兑换码和订单内容仅保存在当前页面内存；保存凭证 TXT 或复制由用户显式操作，不自动写入 localStorage、会话存储或 URL。

配置了 `APP_BASE_PATH` 时，上述路径位于该前缀下。管理员页提供读取、复制和打开公开兑换地址的入口，地址遵循既有公开根地址设置。匿名写请求允许已配置的应用或公开站点来源，管理员写请求仍只接受管理站点来源及 CSRF 凭证。

## 3. 一次性核销、查询凭证与重试

客户端在提交前生成 32 字节安全随机值，编码成 43 字符 base64url，作为本次 `requestKey`；同一原值也用作订单 `queryKey`。页面先提供复制/下载查询凭证，再允许确认兑换。首次响应丢失时，用户仍可用事先保存的凭证查询，订单号可以留空。

服务端分别保存请求用途和查询用途的 SHA-256 摘要与唯一索引，不保存凭证原值。订单号只作标识，不能单独授权；旧兑换码或主邮箱地址也不能用于公开枚举订单。格式合法但未匹配的凭证、错误订单号或二者不匹配返回统一不可查询结果；凭证格式错误单独按参数错误拒绝。

一次性核销在 SQLite immediate 事务成功提交时成立。请求查重、内容指纹核对、码和来源复核、TXT/ZIP 生成、容量检查、加密订单/文件保存、核销记录及审计同事务完成：

- 同一 `requestKey`、相同规范化内容重试，返回同一订单；同键不同内容返回 HTTP 409。
- 不同请求凭证争用同一码，最多一个成功，另一个得到已核销结果。
- 超时或连接中断保留原凭证与原始规范化码列表，重试同次请求或通过查单确认结果。
- 明确失败项可以用新凭证形成新订单重试；页面保留之前已成功订单，避免重复提交成功码。
- 换码/停用先提交则旧码不能核销；旧码核销先提交则原订单有效，后续换码不撤回原交付。
- 文件生成、存储、加密或内部故障使整批回滚，不留下已经核销却没有订单文件的记录。文件下载失败不会反向恢复兑换码，通过原订单重新下载补偿。

订单快照长期保存，不采用旧草案的 24 小时结果过期规则。查询或重复下载只返回本次固定结果，不新增后来的子邮箱、不重新组装当前链接集合、不再次核销。查询凭证遗失时需要管理员查看订单处理，重新生成兑换码不会重建原查询凭证。

## 4. 管理接口

管理 API 仅主节点的站点管理员可访问。沿用 Authorization 会话认证，写请求携带 `/api/admin/session` 返回的 `X-CSRF-Token`；JSON 返回 `{ "data": ... }`，错误使用真实 HTTP 状态及 `{ "error": { "code", "message", "requestId" } }`。

| 方法与路径 | 请求/结果 |
| --- | --- |
| `GET /api/admin/cards` | `q` 邮箱模糊查询、`status`、`page`、`pageSize`；返回主邮箱行、总数及全局 `unissued/unused/redeemed/disabled` 统计 |
| `POST /api/admin/cards/search` | 正文 `code` 完整精确搜索，可附状态和分页；可匹配历史码并定位该主邮箱当前行 |
| `POST /api/admin/cards` | 正文 `mailboxIds`，原数组 1～500 项，校验后去重，整批原子初次生成；返回 `{ items }` |
| `PUT /api/admin/cards/{cardId}` | 正文 `enabled` 明确布尔值和 `revision`，仅修改未核销、未作废的当前码 |
| `POST /api/admin/cards/{cardId}/regenerate` | 正文 `revision`、`requestKey`；换码幂等，返回 `{ card }`，允许原码已经核销 |
| `GET /api/admin/cards/{mailboxId}/history` | 返回该主邮箱各代兑换码及生成/核销/作废时间、当前标志和替换关系 |
| `POST /api/admin/cards/export` | 正文 `mailboxIds`，只导出当前启用且未核销码，TXT 每行一个码，响应附完整性摘要 |
| `GET /api/admin/cards/config` | 返回 `redeemUrl`、`orderQueryUrl` |
| `GET /api/admin/redemption-orders` | `q` 订单号或主邮箱、`status`、`mailboxId`、分页；列表省略每项完整链接，详情再读取 |
| `GET /api/admin/redemption-orders/{orderNo}` | 返回订单详情和固定链接快照 |
| `POST /api/admin/redemption-orders/{orderNo}/download` | 正文 `{}`，下载原 TXT/ZIP，并记录下载审计 |

主邮箱行包含 `mailboxId`、`mailboxEmail`、`mailboxEnabled`、去重子邮箱数量 `childCount`、链接数 `linkCount` 及可空 `card`。码 DTO 包含完整 `code`、`id`、`status`、`enabled`、`revision`、生成/核销/作废时间和替换关系；只向已认证管理员返回。列表默认 50 条，前端可选 20/50/100；批量选择限当前页，查询、分页、刷新时清空。

## 5. 匿名兑换与订单接口

匿名接口只在主节点提供，JSON 必须是单一对象，拒绝未知字段、尾随内容、非法 UTF-8/JSON、类型错误和超限数组。所有凭证使用请求体，不放查询参数。

| 方法与路径 | 正文 | 结果 |
| --- | --- | --- |
| `POST /api/redeem` | `{ "codes": [...], "requestKey": "32字节随机凭证" }` | 新订单 HTTP 201，同次重试 HTTP 200；返回订单 DTO |
| `POST /api/orders/query` | `{ "queryKey": "必填", "orderNo": "选填" }` | 查询授权匹配的固定订单，包含逐项结果和文件元数据 |
| `POST /api/orders/download` | 与查单相同 | 原 TXT 或 ZIP，带附件文件名、`Content-Length`、`X-Content-SHA256` |

客户端规范化支持换行、空白、中英文逗号和分号，保留大小写并按原顺序去重。服务端先验证原始 `codes` 数组 1～100 项及单项非空、128 字节上限，再去重。数组元素中的分隔符不由服务端拆分。

订单 DTO 包含 `orderNo`、`status`（`success/partial/failed`）、`createdAt`、`batch`、成功/失败/子邮箱/链接计数、`items` 和可空 `file`。每项的 `index` 从 0 开始，对应去重后的提交顺序；成功项包含主邮箱和固定链接快照，失败项包含稳定错误码及说明。文件元数据包含 `filename`、`contentType`、`size`、`sha256`。

下载前服务端再次验证持久文件大小和 SHA-256；客户端完整接收并校验后才保存。正文截断或摘要不符时不保存半份文件。没有成功项的订单无文件，下载返回明确不可用错误。

## 6. 数据迁移、保护与恢复

新增迁移 **9：`mailbox-cards-and-redemption-orders`**，正常启动时通过既有有序迁移机制安装，不改历史迁移。

| 表 | 用途与约束 |
| --- | --- |
| `mailbox_card` | 各代兑换码；码摘要全局唯一，局部唯一索引保证每主邮箱最多一个当前码；存码密文、绑定身份、版本、核销/作废时间及替换关系 |
| `redemption_order` | 随机订单号、分别唯一的请求/查询摘要、请求内容指纹、加密结果和原文件、格式/大小/摘要、存储计数 |
| `redemption_order_item` | 固定输入序号、成功/失败项与加密快照；每订单序号唯一 |
| `card_redemption` | `card_id` 唯一，保证每码最多一条成功核销记录；保存加密绑定快照 |
| `card_management_operation` | 管理员身份和换码幂等键，记录同次操作的新码引用 |

兑换码为 `ML-` 加 32 字节随机值的 base64url 编码，以原大小写摘要查询。码、订单结果、包含完整 URL/Token 的逐项快照、交付文件及核销绑定快照使用 SecretVault AES-256-GCM 和不同 AAD；没有加密密钥时拒绝发码或核销。相关秘密不写普通日志、审计字段、URL 或分析埋点。

发码后禁止修改该来源的主邮箱地址、绑定账号或收件模式，核销时再次复核。来源删除后旧码无法兑换，历史与订单保留；同地址重建来源不会继承旧码。普通停用/恢复不会抹除核销或作废事实。

码、订单及查询凭证不进入 `sync_event` 或节点快照/增量 DTO；子节点拒绝管理、兑换、查询及下载。保持现有单可写主节点，不声称支持多主共享事务或跨实例限流。

备份须包含迁移后的 SQLite 数据及对应数据密钥，保留历史数据所需的旧解密密钥。恢复旧备份可能遗漏备份后的核销，应先冻结兑换并核对历史后再开放，不能直接把回退的未核销标志当作可靠库存。TXT 导出不能代替数据库和密钥备份。

## 7. 当前容量、限流与保留

| 项目 | 当前实现 |
| --- | --- |
| 初次生成/码导出 | 原数组 1～500 个主邮箱 ID |
| 公开兑换 | 原数组 1～100 个码；单码修剪后最多 128 UTF-8 字节；实际 JSON 请求体最多 64 KiB |
| 客户端 TXT 追加 | 单文件最多 256 KiB |
| 列表和历史 | 管理列表每页最多 100；单主邮箱历史最多返回 1000 条，超限明确拒绝 |
| 交付链接 | 每主邮箱最多 1000 条，每订单累计最多 5000 条；超限不截断、不核销 |
| 文件与快照 | TXT 未压缩合计最多 8 MiB；最终文件最多 8 MiB＋128 KiB；订单结果 JSON 最多 16 MiB |
| 长期订单存储 | 最多 100000 个订单，累计受控存储计数最多 1 GiB，包含加密结果/文件/逐项/绑定内容及预留开销；达到上限拒绝新兑换，不自动清理旧订单 |
| 匿名固定 60 秒窗口 | 每可信 IP：兑换 30 次、查询 60 次、下载 20 次；非法尝试也计入 |
| 下载资源 | 主进程同时最多 4 个订单下载；匿名每可信 IP 每分钟最多 64 MiB |

限流计数使用 SQLite 持久 KV 和服务器解析的可信 `clientIp`，伪造转发头不能自选来源。超限返回 HTTP 429 和 `Retry-After`；下载结束、取消或异常均释放并发名额。容量是当前固定实现上限，不是已完成大规模性能验收的承诺。

订单、快照及查询凭证摘要目前长期保留，无自动过期任务。长期码有效与订单保留都不延长已经到期的链接。
