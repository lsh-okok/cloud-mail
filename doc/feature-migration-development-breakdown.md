## 1. 排期口径

用户最新范围为 **MX/本地收信＋同一主邮箱下的子邮箱独立链接**，不对接 Outlook/iCloud。此范围优先于历史需求参考；外部邮箱协议、授权、凭据导入和真实外部邮箱联调不再作为开发或验收任务。

按 A 本地基础→B 子邮箱链接→D 本地验证→E 计划/节点→F 上线验收交付。前端可在契约固定后用模拟接口并行，安全与一致性随功能交付。历史卡密规则只适用于 Outlook/iCloud 且排除 MX，故 C1～C3、C-01～C-13 与 R-11 不纳入当前交付；本地邮箱卡密必须另立产品规则。现有注册邀请密钥保持原业务含义。

原先 85～130 人日估算含外部适配和卡密，范围变化后已失效；在剩余工作、已完成证据及上线模式核定后重新估算，不按删除模块简单折算。

| 阶段 | 当前交付范围 | 阶段出口 |
| --- | --- | --- |
| A | 本地主邮箱目录、权限/链接 Token 保护/URL/任务/事件等基础 | 账号与受控域名范围明确；本地读取、安全、事务及任务契约可验证 |
| B | 子邮箱链接管理、导入/批量/导出、公共读取与兼容 | L-01～L-20 在当前范围的对应记录 |
| C | 当前不实施卡密及公开兑换 | 历史 C 条目与 R-11 记不适用及原因，不改造为 MX 卡密 |
| D | 本地来源同步、手动检测、独立 SMTP 验证、停止/复检、报告 | V 项在本地来源范围内的对应记录 |
| E | 每日计划、节点生命周期、快照/增量/保护 | 本地验证计划及 N 项的对应记录，不下发外部邮箱凭据 |
| F | 负载/安全/移动端/前缀、恢复与运维验收 | 当前适用的 A/P/R 项及上线记录 |

X1 多主实例改造、X2 既有本地业务数据迁移在选择该上线模式时成为必做分支，需专项预研与估算；外部账号和历史卡密不自动纳入本地迁移。最终日历工期取决于人员配置和已确认的剩余范围。

建议后端分别负责来源/公共读取和任务/节点，前端负责管理及公开界面，测试从 A 起维护需求编号与证据；共用迁移、Router 与配置由单一责任人整合，避免并行覆盖。

## 3. 关键依赖与并行安排

关键链路为：A1/A2→B1/B2/B3，A3/B2→D1/D3→D4→E1，A3/B1→E2→E3，最后联合验收。来源/平台/链接从第一版开始产生同步事件，不能到节点开发时再补已经发生的历史变更。

- A1/A3 与 A2 可在契约固定后分工；前端 A4 同时实现基础能力及模拟列表。
- B2 与 B3 在 B1 后并行；公共读取先通过完整信封与平台隔离验证，再接入后续本地检测。
- D2 的网络策略与 D3 的 SMTP 配置 UI 可并行；实际收信验证依赖来源与读取隔离通过。
- E2 可在事件模型稳定后与 D 阶段并行；E3 必须复用 B2 的相同策略，不另写简化授权分支。
- F 的测试准备从 A 开始，发布前执行完整联合验收；不等待代码全部完成才编写验收条件。
- 若选择多主，X1 影响事务与调度基础，必须前置到 A，不能在功能结束后作为简单开关补上。

## 5. 验证策略与完成定义

### 自动化验证

1. 用本地邮件样本验证同一 A 中 a1/a2/a3、plus、伪造 To 头、平台及完整信封隔离；分别覆盖账号范围与显式域名范围、关联账号/用户停用及删除。外部邮箱协议与授权不纳入测试任务。
2. 用独立临时 SQLite 验证唯一约束、批次回滚、配置/事件/审计同事务和幂等创建。
3. 人为阻塞读取/SMTP，期间停用来源、修改平台、停止任务/撤销节点，再释放阻塞，核对结果/缓存/统计/终态。
4. 重启活动任务与中断快照，确认不自动重发、历史标识保留、不安装半份配置；事件重复/乱序/缺口触发预期路径。
5. 覆盖所有新旧公共入口、正文/ref/游标、失效后的缓存，使用跨域同名、加号地址、过期、失效来源和不同节点域名样本。
6. 后续自定义 HTTP/SMTP 使用受控传输与 DNS/连接模拟验证错误、超时、全地址检查、IPv4/IPv6、DNS 变化、重定向和证书，核对实际连接目的地。
7. 创建/重试收信任务与复检直接断言 SMTP 调用次数；待确认不是失败重发的触发器。

### 界面与部署验证

在根路径及真实 `/mail` 前缀代理下运行，检查复制/翻页/下载/报告/直接刷新；覆盖含点本地部分、完整邮箱路径和附件资源。以360/390/768/1280宽度和浅/深/系统主题验证关键操作。

公共页面在无登录环境验证，不携带管理 Token；网络故障、旧请求延迟、配置加载失败、隐藏/恢复页面、截断下载都有可理解状态。安全正文确认脚本/表单/远程资源不执行或加载。

### 性能与本地收信联调

模拟规模为1000主邮箱、100000链接、4子节点；正常8秒缓存/5秒同步条件下200并发公共读取持续10分钟，记录P95与错误率，目标P95<1秒、错误率<1%。同时覆盖筛选/全量导出、同邮箱竞争、重快照和验证任务；记录硬件/版本/数据/缓存，不用空数据库首页数据替代。

本地 SMTP/LMTP 实际收信联调用受控测试域名和明确发送范围，记录信封、存储账号与子地址链接结果。独立 SMTP 验证发信在明确授权后单独验收，不等于引入外部邮箱读取集成。上述性能数字是验收目标，尚未执行。

每个完成包提交：实现及迁移、接口契约、相关需求编号、自动化与人工记录、错误/限制说明。最终验收追踪表需逐项覆盖当前适用的 A/L/V/N/M/P 与 R 编号；C 项、R-11 及其外部来源依赖标明“不适用及原因”。未选择既有本地业务迁移时 M 记录不适用，单主发布时双主验收明确“未支持”，不能写通过。
