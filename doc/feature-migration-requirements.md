# 链接管理、卡密管理、邮箱验证、节点管理移植需求文档

版本：1.0  
整理日期：2026-11-13  
依据：当前工作区 `mail-lite` 的管理界面、服务端实现、公共页面及已有测试。  
用途：供新项目进行产品评审、开发拆分、接口设计、数据迁移和验收。

本文不指定开发语言、框架、数据库、中间件或部署产品。HTTP、SMTP、邮件协议、权限和事务要求属于对外行为或一致性要求，实现方案由新项目自行选择。

## 1. 范围与阅读约定

### 1.1 本次交付范围

| 模块 | 管理能力 | 必须同时移植的业务流程 |
| --- | --- | --- |
| 链接管理 | 导入、搜索、筛选、平台规则、有效期、批量操作、导出、统计 | 无需登录的公共取信页面与 JSON 取信接口 |
| 卡密管理 | 按主邮箱生成、查询、复制、导出、停用、恢复 | 无需登录的批量兑换、失败重试、找回当前结果 |
| 邮箱验证 | 来源同步、手动检测、任务详情、停止、复检、CSV、发件配置、每日计划 | 按公开取信规则检测链接，以及发测试邮件后验证实际收信 |
| 节点管理 | 创建独立凭据、状态监控、停用、恢复、永久撤销、删除撤销记录 | 子节点首次同步、增量同步、断线恢复、权限与失联保护 |

四个模块须接入新项目的主邮箱目录、邮件读取能力、管理员认证、公开地址设置和任务基础能力。仅复制四个管理页面不足以完成移植。

### 1.2 需求等级

- **现有基线**：除明确标注外，第 2～8 节描述当前已经存在、移植时应保持的业务行为。
- **新增必做**：第 9 节列出为新项目补充的稳定性要求，不代表原项目全部实现。
- **可选增强**：第 12 节列出可独立排期的功能，不计入本次功能等价移植的默认范围。
- **数据迁移**：第 10 节单独约定。如果只移植功能、不搬运旧数据，可不执行旧数据迁移；仍须实现对应业务规则。

当前不纳入销售库存、预留、出库订单、售后状态和销售统计。邮箱验证可以使用独立验证对象模型，不要求复制原项目历史销售模型和内部表名。

### 1.3 关键业务口径

1. “子邮箱”是已能接收或转发邮件的收件地址。生成取信链接只建立访问关系，不会替用户在邮箱服务商创建别名或配置转发。
2. 卡密不是一次性消费券。重复兑换用于找回该主邮箱**当前仍有效**的链接，结果不是首次兑换时的固定快照。
3. 卡密停用、主邮箱停用、链接过期是不同限制。停用卡密只阻止之后兑换，已交付链接由链接及主邮箱策略控制。
4. 链接检测通过、公共网络可达、实际收信成功是不同结论，不能相互替代。
5. 节点“停用”可使用原凭据恢复；“永久撤销”不可恢复原凭据；“删除记录”只清理已撤销记录。

## 2. 角色、对象与依赖

### 2.1 角色与权限

| 角色 | 可以执行 | 边界 |
| --- | --- | --- |
| 主节点管理员 | 管理四个模块及相关配置，查看任务和报告 | 认证、写操作校验及敏感数据保护均由服务端实施 |
| 卡密持有人 | 打开兑换页、批量提交卡密、复制和下载成功结果 | 不能访问管理接口或邮箱凭据 |
| 取信链接持有人 | 读取该链接允许的邮件 | 不能换收件人、放宽平台限制或删除邮件 |
| 子节点 | 同步允许的配置，提供公共取信 | 不提供管理、兑换、发测试邮件、定时检测及删信能力 |
| 定时任务执行器 | 按已保存并启用的计划创建任务 | 遵守时区、每日认领、并发和发信限制 |

现有系统以管理员为单一管理角色；细分运营、只读、审计等权限属于可选增强。

### 2.2 最小依赖契约

| 依赖 | 至少提供 | 被使用的模块 |
| --- | --- | --- |
| 主邮箱目录 | 稳定 ID、地址、提供商、启停状态、稳定公开标识、配置版本、受控的取信凭据访问 | 全部 |
| 子邮箱关联 | 完整收件地址、归属主邮箱、来源链接 ID、来源策略与修订版本 | 链接、卡密、验证 |
| 邮件读取 | 列表、正文、收件人校验、平台过滤、超时取消、明确错误 | 链接、验证、节点 |
| 平台规则 | 稳定 ID、名称、发件地址/域名、主题关键词、版本 | 链接、卡密、验证、节点 |
| 公开地址配置 | 公开根地址、明确外部站点来源、系统时区 | 链接、卡密、验证、节点接入配置 |
| 管理认证 | 会话校验、写操作防跨站请求校验、注销 | 四个管理模块 |
| 后台任务 | 持久状态、进度、取消、错误、重启处理、容量限制 | 导入、验证 |
| 变更通知 | 数据修改与同步事件一起提交，支持删除与失效 | 链接、节点 |

现有邮件来源包含 Outlook、iCloud 和 MX。链接可用于三类来源；卡密仅用于 Outlook/iCloud 的单个主邮箱。新项目若暂不支持某种来源，须在范围和验收中明确，不得静默接受后再无法读取。

### 2.3 核心对象与关系

| 对象 | 最少业务字段 | 关键约束 |
| --- | --- | --- |
| 主邮箱 | ID、地址、提供商、状态、公开标识、版本/代际 | ID 稳定；公开标识独立于内部 ID |
| 平台 | ID、名称、发件地址列表、域名列表、主题关键词列表、版本 | 被链接引用时不允许直接删除 |
| 取信链接 | ID、主邮箱 ID、完整收件地址、平台 ID、到期时间、创建时间、历史 Token 及摘要 | 主邮箱＋大小写无关完整地址＋平台策略唯一 |
| 卡密 | 主邮箱 ID、唯一卡密摘要、可恢复的加密卡密、启用标志、生成时间、首次成功兑换时间 | 一主邮箱一卡；卡密全局唯一 |
| 验证来源 | 验证对象 ID、主邮箱/链接来源 ID、父子归属、来源/自定义模式、策略指纹、修订 | 同步幂等；冲突不得静默覆盖 |
| 检测任务 | ID、类型、范围/选项快照、状态、数量统计、创建/结束时间、原任务 ID | 已创建任务的目标集不随列表筛选改变 |
| 检测项 | 任务 ID、主/子邮箱快照、链接/策略快照、结果、阶段、处理标志、测试标识、发信信息、说明 | 更新结果与任务计数须原子、幂等 |
| SMTP 发件人 | ID、主机、端口、发件邮箱、加密方式、加密授权码、启停、最近使用时间 | 发件邮箱大小写无关唯一 |
| 每日计划 | 启停、HH:mm、范围、抽样、选项、上次认领日期/任务/错误 | 当前仅一条每日收信验证计划 |
| 节点 | ID、名称、受保护凭据、停用/撤销标志、连接 IP、游标、心跳、错误 | 凭据仅创建时返回；撤销不可逆 |
| 同步事件 | 连续游标、对象类型/ID、版本、数据或删除标记 | 数据与事件同事务产生 |
| 链接访问统计 | 链接 ID、页面次数、JSON 次数、最近访问 | 节点本地统计，与配置事件分离 |

## 3. 通用交互与配置

### 3.1 管理界面

- 提供链接管理、卡密管理、邮箱验证、节点管理入口及系统设置入口；支持直接打开对应页面。
- 桌面支持列表/抽屉，移动端支持卡片/完整表单；360、390、768、1280 像素宽度下核心操作可完成。
- 浅色、深色、跟随系统均可用，默认跟随系统；外观偏好可保存在浏览器。
- 各列表必须有加载、空数据、失败、重试状态；提交时显示进度并阻止重复提交。
- 快速切换筛选、分页或页面时，较早请求的返回不能覆盖最新结果。
- 配置尚未加载成功时禁止保存，防止占位默认值覆盖服务端真实配置。
- 删除、永久撤销、停止任务、启用自动发信等操作明确显示影响范围并要求用户确认。
- 页面关闭、切换或网络中断不得让已持久化的后台任务无故消失；重新打开后能查询状态。

### 3.2 公开根地址与时区

- 生成链接优先使用系统保存的公开根地址，其次使用明确配置的外部站点 Origin，最后使用当前请求来源。
- 反向代理和 HTTPS 部署生成的链接必须使用正确协议、域名、端口；不能信任任意客户端提交的转发头。
- **新增部署适配要求**：部署采用路径前缀时，公开页面调用接口、翻页、导出及复制地址须正确包含前缀，见 R-12。现有生成 URL 支持公开根地址含路径，但全流程仍依赖代理配置，不能视为已经完整覆盖任意前缀部署。
- 系统时区默认 `Asia/Shanghai`，每日计划按系统时区的日历日期判断执行日。
- 对外时间使用含时区的绝对时间，空到期时间表示长期有效；不得使用无法确定时区的字符串判断过期。

### 3.3 管理安全

- 管理接口必须认证；未登录返回未认证，写操作必须进行防跨站请求校验。
- 使用浏览器 Cookie 会话时，保留 HttpOnly、HTTPS 下 Secure、合理的 SameSite 及服务端会话失效机制。
- SMTP 凭据、邮箱凭据及节点凭据不得进入 URL 查询参数、普通日志、错误详情或分析埋点；卡密也不得进入普通日志、错误详情或埋点。
- **新增安全要求**：卡密精确搜索改用受保护请求体，卡密不得进入查询参数，见 R-11。现有管理页通过 GET 的 q 参数搜索完整卡密，新项目不沿用这一传输方式。
- 含卡密、邮件或管理数据的 API 与下载响应禁止缓存；公共页面不得被第三方网站任意嵌入。
- 权限和业务参数都在服务端校验，不能仅依靠按钮隐藏或客户端校验。

## 4. 链接管理

### 4.1 列表、搜索与字段（L-01）

入口基线：`/admin/links`。

列表展示子邮箱完整地址、主邮箱、平台名称、页面 URL、页面访问次数、JSON 调用次数、总访问次数、有效期。未绑定平台显示“全部平台”，无到期时间显示“长期有效”。最近访问时间作为可查询数据保留。

- 搜索支持子邮箱关键字、历史 Token、完整取信页面/JSON URL，以及用于定位的主邮箱标识。
- 可按主邮箱、平台筛选；主邮箱选择支持搜索，不能要求一次加载全部邮箱。
- 默认每页 20 条，可选 20/100/250/500/750；链接列表上限为 750，不能误用其他列表的 100 条上限。
- 单条操作包括复制页面 URL、复制 JSON URL、打开取信页面、修改平台、修改有效期、删除。

### 4.2 导入与链接生成（L-02）

1. 支持粘贴文本、TXT 多文件导入，一批最多 20 个文件；现有前端总文件大小上限 24 MiB，服务端请求体上限 32 MiB。
2. 已选择主邮箱时，本批地址均绑定该主邮箱。
3. 未选择主邮箱时，每份文件首个非空行为主邮箱地址或合法的主邮箱凭据行，之后为子地址。完整凭据行可用于创建缺失的主邮箱，凭据处理必须走主邮箱模块的受控入口。
4. 子地址可按换行、逗号、空格、Tab、分号分隔；支持 BOM 和空行，地址去首尾空白并标准化大小写。
5. 当前同时提供粘贴文本与文件时，以文件为准；界面须明确提示，不能让用户误以为两者均被导入。
6. 本批可指定平台、到期时间。主邮箱、平台、地址均需校验；MX 子地址必须属于绑定的 MX 域名。
7. 已存在相同“主邮箱＋完整收件人＋平台策略”的链接时复用原记录，保留原 Token、期限和规则，不因重复导入重新计时。
8. 非法项记录文件名、行号及原因，其余合法项继续；当前每 500 条链接事务提交。
9. 返回后台任务 ID，显示排队/运行/完成/部分失败/失败、输入行总数、已处理行数、失败计数和最多 100 条错误。进度按输入行计，一行可能包含多个地址。
10. 队列满时明确拒绝；服务重启后原排队/运行任务标为中断失败，可重新提交并复用已成功记录。

### 4.3 选择与批量变更（L-03）

- 支持逐条、当前页、跨页选择；跨页全选必须先指定主邮箱，仅选择该邮箱在当前搜索与平台筛选下的链接。
- 搜索、主邮箱或平台筛选改变后清空选择。
- 一次处理 1～10000 个链接 ID，先校验数量再去重；超限要求缩小范围。
- 打开批量操作窗口时固定 ID 快照，并展示数量。之后新增的链接不得进入这次操作。
- 批量动作：设置平台、设置有效期、删除。清空平台表示不限平台。
- 平台/有效期修改整批原子提交：ID 不存在、目标平台不存在、时间不合法或唯一性冲突时，整批不修改。
- 删除链接不删除邮件；删除后页面与 JSON 同时失效，统计一并清理。重复删除不存在链接可按幂等成功处理。
- 删除主邮箱须级联处理其链接并产生同步删除事件。

### 4.4 有效期（L-04）

- 预设：1/3/7/15/30 天、长期有效、指定日期时间。
- 按天设置从保存时计算；保存后到期时刻固定，不因访问顺延。
- 可以设为过去时间以立即过期，也可以改为未来或长期有效恢复访问。
- 过期限制覆盖页面、JSON、正文读取及旧游标；不能只限制页面入口。

### 4.5 平台规则（L-05）

字段：稳定 ID、名称、发件邮箱列表、发件域名列表、可选主题关键词列表。

- 名称必填、最多 80 字符；至少提供一个合法发件邮箱或域名。
- 列表去空白、大小写无关去重。发件邮箱精确匹配，域名匹配本域及子域，不能误命中相似后缀域。
- 发件邮箱与发件域名为“或”；有主题关键词时，还需命中任一关键词，关键词大小写无关。
- 收件人约束始终成立。先按收件人及平台过滤，再选最新邮件，不能先取全邮箱最新一封再过滤。
- 平台更名保留 ID，旧 URL 的名称标签仍可解析；实际规则由 ID 决定。
- 平台仍被链接引用时拒绝删除；规则变化使相关旧分页游标失效。

### 4.6 公共 URL 与兼容（L-06）

| 类型 | 基线路径 |
| --- | --- |
| 当前页面 | `/show/{平台段}/{主邮箱公开标识}/{子邮箱本地部分}` |
| 当前 JSON | `/api/mailboxes/{平台段}/{主邮箱公开标识}/{子邮箱本地部分}/messages` |
| 历史 Token 页面 | `/m/{token}` |
| 历史 Token JSON | `/api/mailboxes/{token}/messages` |
| 其他历史可读路径 | 使用内部主邮箱 ID 和完整收件地址的 `/m/...` 及对应 JSON 路径 |

- 主邮箱公开标识为稳定的 10 位随机标识，编辑、重新导入及重启不改变；不暴露内部主键。
- `p0` 表示不限平台，兼容历史 `all`；绑定平台时使用“清理后的名称~平台ID”。
- 不限平台的链接允许替换为已存在的平台段做额外过滤，各变体仍属于同一链接并共用统计。
- 绑定了平台的链接不能通过改成 `p0` 或其他平台绕过限制；未知平台直接按未找到处理。
- 同一主邮箱下不同域名具有同名子地址时，省略域名的短链接必须拒绝歧义解析。使用完整地址路径或精确 Token 路径访问，不得随意选中某个邮箱。
- 查询参数不能覆盖链接绑定的主邮箱、收件人、平台及有效期。

### 4.7 公共取信行为与隔离（L-07）

- 持有链接即可按其权限取信，无需管理登录；不提供公开删信能力。
- 页面默认显示符合约束的最新一封；兼容 `?recent=1` 列表模式及最新/最早排序。
- JSON 列表最大 20 封；显式 `limit=1` 获取单封。返回收件人、邮件项及适用的排序、下一游标、是否有更多等信息。
- “没有符合条件的邮件”返回正常空结果，与上游故障区分。
- 列表、正文、历史 Token、邮件 ID、签名引用和分页游标均重新验证链接、主邮箱状态、收件人、平台及节点就绪状态。
- 上游读取完成后需防止失效配置返回旧结果；取信过程中主邮箱停用或策略变化，不能继续泄露已不允许的数据。
- iCloud 隐藏邮箱转发不能只看 To：需保留原始收件地址核验，加号地址严格隔离；MX 按 SMTP 信封收件人校验。邮件适配层必须保留这些信息。
- 邮件 HTML 在隔离容器展示，禁止脚本、表单和远程跟踪资源，不得访问管理页面上下文。正文最大读取 2 MiB。

分页游标绑定账号、链接、收件人、平台、规则版本、排序、账号代际与过期时间；服务端保存稳定快照，URL 只含短引用。现有基准为 30 分钟有效、每节点最多 64 会话、单快照 16 MiB、总 64 MiB；重启、回收或策略变化后提示刷新。重复使用同一有效游标应保持一致结果。

错误须区分：不存在/无权限 404、过期 410、参数或游标错误 400、繁忙 429、上游失败 502、未就绪 503。若新项目统一错误结构，可调整表现形式，业务语义不能丢失。

### 4.8 导出与统计（L-08）

- 链接 TXT 导出覆盖当前**全部筛选结果**，不受当前页或勾选范围限制。
- 每行格式：`子邮箱----公共页面URL`；UTF-8；禁止缓存。大导出显示进度、阻止重复触发。
- 该文件只是交付清单，不含完整规则、Token、统计和元数据，不能作为完整迁移备份。
- 每条链接分别统计页面 GET、JSON GET、合计及最近访问时间；同链接查询参数、历史路径和平台变体归入同项。
- 已存在链接即使过期或上游失败仍计一次；未知链接、HEAD、管理端查询、复制操作不计。
- 计数原子持久化，重启不丢失；不生成配置同步事件。当前每个节点各自统计，主节点不汇总子节点访问量。

## 5. 卡密管理与公开兑换

### 5.1 业务模型与状态（C-01）

一卡固定绑定一个 Outlook/iCloud 主邮箱，一主邮箱最多一卡。卡密不存在独立有效期、次数额度、换绑或订单依赖。

| 状态 | 判定 |
| --- | --- |
| 未生成 `unissued` | 主邮箱尚无卡密记录 |
| 未兑换 `unused` | 卡密启用、从未成功交付链接 |
| 已兑换 `redeemed` | 卡密启用、已有首次成功兑换时间 |
| 已停用 `disabled` | 卡密停用，展示优先级高于兑换状态 |

停用不清除首次兑换记录；恢复后依据是否曾成功兑换显示未兑换/已兑换。主邮箱状态独立展示。

### 5.2 管理列表与操作（C-02）

入口：`/admin/cards`。以主邮箱为行，尚未生成卡密的主邮箱也要显示；排除 MX。

- 字段：主邮箱、类型、主邮箱状态、该主邮箱全部链接数、完整卡密、卡密状态、生成时间、首次兑换时间。
- 链接数不是当前可兑换数量，不应标成“可用链接数”。
- 按主邮箱模糊搜索或完整卡密精确搜索；支持四种状态筛选。
- 顶部四种状态数量统计覆盖全体主邮箱，不随当前搜索条件改变。
- 默认每页 50，可选 20/50/100；切换搜索、状态、页码、页容量或刷新后清空选择。
- 单条生成、复制、停用、恢复；当前页勾选后批量生成、复制、TXT 导出。
- 当前没有跨页全选、全筛选导出、批量停用/恢复、卡密重置或轮换；不能与链接页的批量范围混用。
- 提供复制/打开公开兑换页地址，地址读取失败可重试。

### 5.3 生成、导出与并发（C-03）

1. 一次生成请求接受 1～500 个主邮箱 ID，校验原数组数量后去重。
2. 主邮箱须存在、启用且类型受支持；允许主邮箱暂时没有子邮箱链接。
3. 安全随机生成不可预测且全局唯一的卡密。现有格式为 `ML-` 加 32 字节随机值的 URL 安全编码；迁移旧卡密必须保留原值和大小写。
4. 重复生成返回原卡密，保留启停、生成时间、首次兑换时间。
5. 整批原子提交：任一主邮箱不合法，则整个批次不生成新卡。
6. 并发为同一主邮箱生成，只能留下同一卡密；所有成功请求获得相同结果。
7. 成功后显示主邮箱与卡密对应关系、数量，支持复制和下载。
8. 管理 TXT 仅含卡密，每行一个，范围为当前勾选且已有卡密的行或本次生成结果，不包含邮箱凭据。
9. 停用/恢复不得改变卡密内容、主邮箱绑定及两项时间。

### 5.4 公开批量兑换（C-04）

入口：`/redeem`，接口基线：`POST /api/redeem`，均仅主节点提供。

- 支持粘贴和单个 TXT 文件；文件内容追加到输入，不自动提交。
- 支持换行、空格、中英文逗号、分号；去空白、空项，按原顺序去重；保持卡密大小写。
- 实时显示去重数量，一批最多 100；客户端 TXT 上限 256 KiB。
- API 接受 JSON，原始 `codes` 数组 1～100 项，再去重；请求体最大 64 KiB，单卡非空且不超过 128 字节。
- 非法 JSON、未知字段、尾随内容、类型错误明确拒绝。提交期间禁止重复操作；现有前端等待上限为 60 秒。
- 每张卡分别返回成功/失败；业务失败不阻断同批其他卡。存储等内部故障须整体回滚并返回服务异常。
- 结果显示成功卡数、失败卡数、交付链接总数及逐卡原因；重复兑换明确显示“结果已找回”。
- 支持仅重试失败卡，保留之前成功结果，替换失败项的新结果。
- 同一连接来源每分钟最多 30 次请求；超限返回 429 及可重试时间。
- 公开兑换无需管理员会话，但需拒绝跨站浏览器提交。

成功项包含卡密、是否重复兑换、主邮箱地址、链接列表；每条链接含完整子邮箱、精确 URL、平台名称、到期时间。成功响应可展示主邮箱地址，但不得返回主邮箱密码、Client ID、Refresh Token、应用专用密码或代理凭据。

### 5.5 有效链接与找回规则（C-05）

每次兑换重新校验并组装当前结果：

1. 卡密存在且启用，绑定主邮箱存在、启用且类型受支持。
2. 仅交付该主邮箱当前名下的链接；排除已到期、到期格式错误及引用失效平台的链接。
3. 短链接必须实际精确解析到相应收件人及平台。跨域同名等情况可能产生歧义时，回退精确 Token 链接，不能交付错误或放宽限制的链接。
4. 没有可交付链接时本卡失败，不写首次成功兑换时间。
5. 至少交付一条后才写首次成功时间；之后成功不覆盖该时间。
6. 重复兑换可看到新增的有效链接，已删除/过期链接不再交付，不返回第一次兑换的静态快照。
7. 并发兑换同一卡密时，所有结果归属同一主邮箱，仅一个成功请求标识首次兑换，其余标识找回。

生成和兑换不连接邮箱做健康检测；兑换成功只说明已交付符合配置条件的链接。

### 5.6 成功结果交付与保护（C-06）

- 每条链接可打开、复制；支持复制全部成功结果或下载 TXT。
- 公开 TXT 每行 `子邮箱----取信链接`，只包含成功结果，不含卡密、主邮箱、失败说明和凭据；采用 UTF-8 BOM，文件名避免重复覆盖。
- 卡密只存安全摘要及受保护的可恢复加密值，不能明文持久化。
- 卡密管理列表可向已认证管理员返回完整卡密以支持复制/导出；公开接口不得按邮箱查询、枚举或获取未提交的卡密，但兑换响应允许回显本次提交的卡密以关联结果。
- 停用卡密不撤回已经交付的链接。需要收回读取能力时，应按主邮箱/链接策略另行处理。
- 子节点不接收卡密数据，不提供公开兑换入口。

## 6. 邮箱验证

### 6.1 页面及两种检测（V-01）

入口：`/admin/verification`，包含“检测任务”和“检测配置”。无需销售库存导入或出库即可使用。

| 类型 | 操作 | 通过的含义 | 不能据此得出的结论 |
| --- | --- | --- | --- |
| 链接检测 | 系统来源走内部公开取信逻辑，自定义链接走 HTTP | 本次对应检测逻辑可成功执行 | 不能说明公网一定可达或测试邮件已经收到 |
| 收信验证 | SMTP 发带随机标识的邮件，再轮询相应取信结果 | 找到本次测试标识 | 不保证未来任何邮件均能收到 |

来源同步、创建/停止/复检任务、SMTP 配置和每日计划仅在主节点运行。

### 6.2 来源同步与冲突（V-02）

- 页面进入时自动同步，提供“同步邮箱与链接”；现有手动页面提交前再次同步，定时任务在服务端执行前同步。
- 同步读取启用主邮箱及名下链接，保留稳定来源 ID、完整地址和父子归属；重复同步不得生成重复验证对象。
- 展示启用主邮箱数、子邮箱链接数、已同步数、冲突数；冲突列表须能定位到邮箱和具体原因。
- 同地址不同主邮箱、跨来源或跨平台产生归属冲突时跳过，不得任意合并、覆盖或丢失原映射。
- 可补齐符合条件的空链接，不得覆盖用户已配置的自定义链接。
- 关联来源需要实时判断资格：主邮箱停用/删除、链接删除/过期、收件人或父邮箱变化、平台缺失或不可解析，均须排除或给出明确原因。
- 保存策略指纹，包含来源链接、实际生效链接、主邮箱、平台以及链接模式/修订。历史结果必须绑定检测时策略，策略变化后不能冒用为最新有效结果。
- 验证用分组与主邮箱管理分组在现有系统中不是同一套分组；新项目应明确区分。是否统一属于产品选择，不能仅因名称相同自动映射。

**移植补充见 R-01：新项目所有任务创建入口都必须在服务端同步来源。当前手动 API 本身不自动同步，不能照搬这个差异。**

### 6.3 手动检测参数与限制（V-03）

| 参数 | 允许值 | 默认 |
| --- | --- | --- |
| 类型 | 链接检测、收信验证 | 按用户选择 |
| 页面范围 | 全部启用主邮箱、指定一个或多个主邮箱 | 全部 |
| 每主邮箱抽样 | 全部、随机 1/3/5 个子邮箱 | 1 个 |
| 单次请求超时 | 1～60 秒 | 10 秒 |
| 检测并发 | 1～10 | 5 |
| 收信等待 | 5～300 秒 | 60 秒 |
| 发信间隔 | 200～10000 毫秒 | 1000 毫秒 |
| 单任务规模 | 最多 20000 个子邮箱 | 按范围和抽样确定 |
| 同时活动任务 | 最多 4 个 | 达限拒绝并说明 |

- 指定主邮箱需至少一个有效项；同步后已删除或停用的选项不能继续提交。
- 指定验证主邮箱/子邮箱的 ID 原数组为 1～500 项，先校验原长度再去重；原验证接口 ID 为正整数，与主邮箱目录的来源 ID 分开映射。新项目若调整 ID 形式，须保留数量限制和明确映射。
- 无可检测项时拒绝创建，不能生成“0 项成功完成”的任务掩盖配置问题。
- 候选项、链接、策略和选项先形成持久快照，再异步执行；前端退出不取消已创建任务。
- 收信验证创建前必须明确确认发测试邮件；没有可用发件人时拒绝。
- 创建后展示任务编号、排队状态和实际目标数量，并能进入详情。
- 原服务端还支持指定子邮箱及检测分组范围，当前手动页面未暴露；是否在新界面开放可单独决定。

### 6.4 链接检测执行与结论（V-04）

系统来源直接复用公开链接解析、收件人核验及平台过滤，最多读取 20 封匹配邮件；不向自身地址发回环 HTTP。不能仅凭 URL 看似本站就绕过安全校验，内部来源必须由受信映射确定。

自定义链接通过 HTTP GET 检测，每次解析、实际连接与重定向均遵守网络访问防护。不同结论按以下语义呈现：

| 情况 | 结果 |
| --- | --- |
| 自定义链接最终有效响应 2xx/3xx | 通过 |
| 地址格式错误、明确 4xx（408/429 除外） | 失败 |
| 网络异常、超时、地址安全拦截、408/429/5xx | 待确认 |
| 系统来源读取正常，包括没有匹配邮件的正常空结果 | 链接检测通过 |
| 系统来源暂时读取失败 | 待确认 |
| 来源归属或策略与任务快照不一致 | 失败或以明确原因停止该项 |

系统内部检测通过只说明取信逻辑可执行。验证公网域名、证书和外部访问能力，需要额外从外部网络进行验收。

### 6.5 实际收信验证（V-05）

1. 每个检测项生成随机且不可混淆的本次测试标识，写入测试邮件主题及正文。
2. SMTP 调用前持久保存标识、发件邮箱和阶段，避免发送结果不确定时重新发信。
3. 系统关联来源在发信前及实际取信前复核当前来源与策略，防止排队期间配置变更后错发、串信或误判。现有自定义链接按任务快照执行，复检时再校验修订；对所有模式统一进行运行中复核属于 R-04 的新增要求。
4. 按完整收件人及平台过滤后的邮件中查找标识；内部来源检查主题、纯文本及 HTML。自定义页面读取最多 2 MiB。
5. 每 3 秒轮询一次，在等待期限内找到本次标识才算通过。仅 HTTP 成功、只有旧邮件或其他任务标识均不能算通过。
6. 等待到期未找到标识为待确认。平台规则可能过滤测试邮件时显示明确提示，不直接断言邮箱失效。
7. SMTP 报错或投递状态不确定，按待确认处理，保留测试标识供复检查询。
8. 多任务共用发信节流和发件轮换顺序；实际发信串行，读取检测可按参数并发。
9. 发件池账号已停用/删除时不再选用；当前执行中的取消要能传递到网络等待。

### 6.6 任务与单项状态（V-06）

| 对象 | 状态/阶段 |
| --- | --- |
| 任务 | 排队 queued、运行中 running、已完成 completed、已停止 stopped、失败 failed |
| 单项结果 | 通过 passed、失败 failed、待确认 pending |
| 单项阶段 | 排队 queued、检查中 checking、发信中 sending、等待收信 waiting、已结束 finished、中断 interrupted |

单项同时保留“是否处理完成”与阶段。“待确认”既可能是已完成但结论不确定，也可能是尚未处理，不能只用结果值计算进度。

- 任务列表显示编号、类型、处理进度、通过/失败/待确认数量、状态、创建时间；按编号倒序，默认每页 25。
- 详情默认每页 25，支持按通过/失败/待确认筛选，展示子邮箱、主邮箱、结果、说明、HTTP 状态（内部检测可为空）、发件邮箱、检测时间和阶段；保留开始/发送时间。任务/详情接口页容量上限 750，当前界面固定 25。
- 运行任务约每 5 秒刷新，浏览器标签页隐藏时暂停轮询；重新显示时恢复。
- 已结束任务与检测项历史持久保存，即使原邮箱删除，仍能查看当时的邮箱及来源快照。
- 单项结果与任务统计原子更新，重复回调不能重复累计。

### 6.7 停止、重启与复检（V-07）

- 停止需要确认，保留已完成结果，取消尚在等待的操作；未处理项注明中断，不能继续发信。
- 停止后的迟到结果不能把任务改回运行、覆盖终态或重复增加统计。
- 服务重启后排队/运行任务转为失败，未完成项说明重启中断；保留测试标识，不能自动恢复发信。
- 复检只允许原任务结束后发起，创建新任务，保留原任务及父子关联。
- 候选来自原未通过项；已通过项不再检测。
- 当前来源仍存在、可检测，且链接、来源归属、模式及策略未变化，才能复检；其余逐项跳过并保存原因。
- 显示原未通过数量、本次复检数量、原任务编号和跳过列表；无符合项时明确拒绝。
- 收信复检沿用原标识、原发件邮箱、原发送时间，**绝不重新发 SMTP 邮件**。没有原标识则提示新建并确认发信任务。
- SMTP 超时但邮件实际到达的场景，应能由复检通过原标识确认，发信调用次数不得增加。

### 6.8 默认 SMTP 与发件池（V-08）

- 默认 SMTP 配置一套，支持多个发件池账号；池存在时，优先使用其中启用且可用的账号。
- 池存在但全部停用或不可用时明确失败，不静默切回默认账号。
- 字段：主机、端口、完整发件邮箱、SSL/TLS 或 STARTTLS、授权码；池账号另有启停及最近使用时间。
- 端口 1～65535；主机合法、最长 253 字符并通过网络地址校验；授权码最多 500 字符。首次配置必填，编辑留空保留；默认配置支持明确清除授权码。
- 账号邮箱大小写无关唯一；支持编辑、启停，确认后删除。
- 只允许加密传输，TLS 最低 1.2，验证服务器证书；STARTTLS 不可用时失败，不能回退明文认证。
- 授权码加密保存，读取配置只返回“是否已配置”，不能返回明文或密文；解密值仅用于受控执行。
- 预设包含 163、126、Yeah、QQ/Foxmail、Yahoo、iCloud、Gmail、阿里个人邮箱。iCloud 为 `smtp.mail.me.com:587 + STARTTLS`，其余现有预设为对应主机的 `465 + SSL/TLS`。
- 预设自动填主机/端口/加密方式，邮箱和授权码由用户填写，且预设值可修改；提供各服务商授权码/应用专用密码说明。

### 6.9 自定义链接与 SMTP 的网络防护（V-09）

- 自定义链接最长 8192 字符，只允许 HTTP(S)，拒绝 URL 用户名/密码、换行/Tab、回环、私网、链路本地、云元数据及保留地址。
- DNS 返回任一不允许的地址则拒绝；实际连接使用校验过的地址，防止校验与连接间 DNS 变化。
- 每次重定向重新校验，最多 5 层；不能通过系统代理配置绕过地址限制。
- SMTP 同样校验目标主机解析与实际连接，拒绝头部注入。
- 内部来源通过受信映射直接读取，允许本机部署，不与任意自定义链接的安全策略混为一谈。
- 新项目若要支持企业内网 SMTP，须作为显式可配置的例外并单独验收，不能默认放开全部私网地址。

### 6.10 每日计划（V-10）

- 当前一条每日收信验证计划，字段：启停、`HH:mm`、全部或指定检测分组（含未分组）、每主邮箱全部/1/3/5 抽样及检测参数。
- 持久化默认：停用、02:00、全部、抽样 1；不能把配置组件加载前的 09:00 占位值当成默认。
- 使用系统时区，展示时区、上次执行时间、任务、状态、错误及下次执行时间。
- 启用计划前明确确认自动发送测试邮件，并校验可用 SMTP。
- 提供“立即执行已保存计划”，仍需发信确认，不使用尚未保存的表单值。
- 每次运行前在服务端同步来源，纳入新增来源，排除停用/删除/过期来源。
- 约每 15 秒检查；当天尚未执行且已过计划时间，则执行当天一次。服务恢复可补当天，不补发全部历史日期。
- 当天认领日期与任务快照一并持久化，防重复触发/重启后重复自动发信；多实例约束另见 R-03。
- 上次计划任务还在排队/运行时，不创建重叠计划任务，同时遵守全局 4 个活动任务上限。
- 手动立即执行不占用当天自动执行日期。
- 当天自动执行因无候选或无发件人等失败，记录当日错误，不在当天无限重试发信。

### 6.11 CSV 报告（V-11）

- 按任务导出全部检测项，不受详情当前页或结果筛选限制。
- UTF-8 BOM，顺序稳定。字段至少：子邮箱、主邮箱、链接、结果、HTTP 状态码、说明、检测时间、发件邮箱、阶段、开始时间、发信时间。
- 保留检测时主邮箱快照，源对象删除后仍可追溯。
- 文本字段防电子表格公式注入；不得导出邮箱凭据、SMTP 明文/密文或节点凭据。

## 7. 节点管理与同步

### 7.1 目标与边界（N-01）

多个独立部署的子节点同步主节点配置，在不同域名下按同样路径提供公共取信，分散读取请求。现有能力不包含主节点自动故障切换、长期离线读取或对子节点服务器的开关机操作。

主节点保有管理与写权限。子节点禁止管理、公开兑换、验证发信及删信。每个节点使用独立凭据和独立数据目录。

### 7.2 创建接入凭据（N-02）

- 管理入口 `/admin/nodes`，节点名称去首尾空白后必填，1～80 字符。
- 创建生成稳定 ID 和独立的安全随机接入凭据；凭据只在创建响应及创建完成窗口显示一次。
- 提供可保存的接入配置：主节点根地址、节点 ID、节点凭据、节点角色、监听设置、独立数据位置。
- 后续列表、启停响应、状态查询不返回凭据；找不到凭据时应创建新节点，不提供普通列表取回。
- 默认要求 HTTPS 主节点地址；回环测试允许 HTTP，受控内网 HTTP 必须显式开启。
- 子节点不需要管理员密码；复制接入配置时清晰提示保存凭据及使用独立存储。

### 7.3 状态展示（N-03）

- 总览显示未撤销节点数、在线数、主节点当前同步游标。
- 每个节点显示名称、ID、状态、连接 IP、最近心跳/同步时间、节点游标/主游标、待同步事件数和最近错误。
- 首次同步显示快照已完成条数、总条数和进度。
- 状态优先级：已撤销、已停用、初次同步、在线、未连接/离线。
- 当前在线展示阈值为最近 15 秒内有心跳且未停用/撤销；管理页约每 5 秒刷新，也可手动刷新。
- 在线是管理界面的连接状态，不能替代“已经追上配置且可取信”的就绪判断。
- 连接 IP 来自主节点观察到的成功心跳连接地址，支持 IPv4/IPv6，离线/停用时保留最后记录。默认不采信任意 `X-Forwarded-For`。
- 非法或未授权心跳不得修改 IP、游标或节点状态；启用后须等新心跳，不能立刻展示在线。

### 7.4 停用、启用、撤销和删除（N-04）

| 操作 | 条件 | 结果 |
| --- | --- | --- |
| 停用 | 凭据尚未撤销 | 拒绝后续接入，保留 ID、原凭据、游标及配置 |
| 启用 | 已停用且未撤销 | 原凭据恢复接入，运行中的子节点自动重连并补齐变更 |
| 永久撤销 | 尚有节点记录 | 原凭据永久失效，恢复接入需新凭据 |
| 删除记录 | 必须已永久撤销 | 从管理列表移除，旧凭据仍不得接入 |

- 永久撤销及删除记录必须明确确认；按钮和文案不能让用户误把永久撤销当临时下线。
- 停用/启用重复提交应保持幂等；已撤销节点不能通过启用恢复。
- 禁止直接删除启用或停用记录，须先撤销。
- 启用不会启动已关机服务器；服务器/进程恢复且原凭据未撤销时自动重连。
- 已通过认证但尚未提交的心跳，也不能覆盖管理员刚设置的停用/撤销状态。

### 7.5 首次同步与增量同步（N-05）

1. 首次使用固定一致性快照，每页 1000 条；阶段数据与分页进度持久保存，中断后继续。
2. 快照与创建后的主节点变更分开处理，不能分页读到多个时间点混合的数据。
3. 完整快照安装需原子切换，完成前不开放公共取信。
4. 快照安装后拉取连续增量事件，每批 500 条，追到本次主节点游标并成功确认后才就绪。
5. 数据、版本与事件同事务写入；同步支持新增、修改、删除、配置代际失效。
6. 重复事件不重复产生副作用；事件乱序、缺口或游标不一致不得静默跳过。
7. 事件保留基线 30 天；游标过旧或异常时重新初始化快照。
8. 快照会话有效 15 分钟，绑定所属节点；过期或主节点重启后安全重新开始，不能安装半份快照。
9. 默认约每 5 秒拉取；同步后失效相关邮件、分页和凭据缓存，防止旧请求重新填入过时数据。
10. 临时停用期间的变更恢复后要补齐；若已超出事件保留期则重新快照。

### 7.6 失联保护与凭据边界（N-06）

- 初次同步未完成、重新快照期间、尚未追上配置时不提供取信。
- 与主节点连续无法成功同步超过 120 秒停止取信；不能无限使用本地旧策略。
- 收到明确停用/撤销/凭据无效响应后立即转未就绪，不等待 120 秒。
- 提供存活与就绪检查：存活只表明进程运行；未就绪检查返回 503。
- 子节点同步主邮箱、链接、平台、分组及必要设置，不下发管理员密码、卡密、SMTP 发件凭据、Outlook Refresh Token 或原始公共链接 Token。
- iCloud 取信所需凭据须在子节点本地受保护保存；Outlook 的短期读取 Token 按需向主节点申请，在内存短期缓存，不允许申请写权限。
- 不应因节点使用不同域名改变链接绑定策略；配置传播存在轮询延迟，要在运维说明中写明。
- 被撤销或停用节点在完全网络隔离时无法立刻获知状态，120 秒失联上限是现有约束，不能承诺零延迟撤销。

## 8. 接口与模块联动契约

以下为现有业务接口清单，供新项目设计及兼容核对。管理端路径可按新项目约定调整；若承接已有外部调用，须保留兼容层。已分发公共链接和卡密的兼容策略见第 10 节。

| 能力 | 现有 HTTP 入口 | 核心输入/输出 |
| --- | --- | --- |
| 链接列表/选择 | `GET /api/admin/links`、`GET /api/admin/links/selection` | 搜索、主邮箱、平台、分页；数据/总数或明确 ID 集合 |
| 导入 | `POST /api/admin/import` | 类型 links、文本/文件、主邮箱、平台、到期；后台任务 |
| 导入任务进度 | `GET /api/admin/jobs` | 最近最多 30 条任务，按任务 ID 关联进度及错误 |
| 系统设置 | `GET/PUT /api/admin/settings` | 公开根地址、系统时区等共用配置 |

| 链接导出 | `GET /api/admin/links/export` | 当前筛选；全量 TXT |
| 平台规则 | `GET/POST /api/admin/platforms`、`DELETE /api/admin/platforms/{id}` | 发件人规则及引用约束 |
| 卡密列表/生成 | `GET/POST /api/admin/cards` | 搜索/状态/分页或主邮箱 ID 数组 |

| 公开兑换 | `POST /api/redeem` | codes；逐卡结果及当前有效链接 |
| 验证来源 | `GET /api/admin/mail/mapping/preview`、`POST /api/admin/mail/mapping` | 预览/同步结果及冲突 |
| 验证任务 | `GET/POST /api/admin/mail/inspections` | 范围/类型/选项；分页或新任务 |
| 详情/报告 | `GET /api/admin/mail/inspections/{id}`、`GET .../{id}/export` | 详情分页或全任务 CSV |
| 停止/复检 | `POST .../{id}/stop`、`POST .../{id}/retry` | 停止结果或关联原任务的新任务 |
| SMTP 配置 | `GET/PUT /api/admin/mail/settings` | 默认配置与是否有授权码 |
| 发件池 | `GET/POST /api/admin/mail/senders`、`PUT/DELETE .../{id}` | 发件人配置、启停，始终脱敏读取 |
| 每日计划 | `GET/PUT /api/admin/mail/inspection-schedule`、`POST .../run` | 计划、上次/下次执行信息 |
| 节点列表/创建 | `GET/POST /api/admin/nodes` | 状态列表；新节点和仅一次凭据 |
| 节点启停 | `PUT /api/admin/nodes/{id}/status` | disabled 明确布尔值 |
| 节点撤销/删除 | `DELETE /api/admin/nodes/{id}`、`DELETE .../{id}/record` | 永久撤销/删除撤销记录 |
| 内部同步 | `/internal/snapshot`、`/internal/events`、`/internal/heartbeat` | 节点认证、快照进度、连续游标 |
| 内部读取授权 | `/internal/tokens`、需要时的 `/internal/mx/read` | 只读短期授权/受控读取 |
| 健康检查 | `GET /health/live`、`GET /health/ready` | 角色及存活/就绪 |

通用契约：严格校验字段、类型、数组大小和未知动作；管理端页码分页返回项目、总数、页码和页容量，公共取信使用游标分页；时间含时区。公开兑换返回逐项业务错误；导入任务凭 ID 在任务列表中关联，现有无单独按 ID 查询路由，新项目可提供等价的单任务查询。不能混用“请求已受理”和“任务已成功”。错误文本须可理解且不含密钥或内部堆栈。

### 8.1 跨模块变更影响

| 事件 | 链接/公共取信 | 卡密 | 验证 | 节点 |
| --- | --- | --- | --- | --- |
| 主邮箱停用 | 所有读取入口受限 | 不允许生成，兑换失败 | 排除来源/执行前复核 | 下次同步生效，失联保护兜底 |
| 主邮箱删除 | 关联链接删除 | 不再交付 | 保留历史，当前来源失效 | 同步删除及缓存失效 |
| 链接新增 | 新链接可按策略读取 | 下次兑换可交付 | 下次同步纳入 | 同步新增 |
| 链接过期/删除 | 页面、JSON、旧引用不能继续读取 | 不交付失效链接 | 排除/失败，旧任务记录保留 | 同步变更或本地按绝对时间过期 |
| 平台规则变化 | 重新过滤，旧游标失效 | 交付当前正确策略 | 策略指纹变化，复检旧项跳过 | 同步规则并失效缓存 |
| 卡密停用 | 链接自身规则继续生效 | 后续兑换失败 | 不影响邮箱验证 | 不下发卡密状态 |
| 节点停用/撤销 | 相应子节点停止取信 | 主节点兑换继续 | 主节点验证继续 | 拒绝同步/授权，执行停止服务边界 |

主节点本地策略变更提交后立即按新策略校验；子节点存在同步周期内的传播延迟。迁移验收须分别测试本地生效和子节点追平后的生效。

## 9. 新项目新增必做的稳定性要求

以下为移植补充，不应误解为原项目全部已有。它们不限定实现技术，但属于新项目上线验收范围。

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| R-01 | 所有手动/API/定时任务创建统一执行“服务端同步来源→资格校验→固定目标与策略快照→创建任务”；不能仅依赖前端先同步 | 绕过管理页面直接调用创建 API，新来源也能进入任务，失效来源被排除 |
| R-02 | 手动收信验证支持创建请求幂等键；同一请求重试返回同一任务，不得重新选样、生成测试标识或发第二遍邮件；同键不同参数拒绝 | 模拟请求超时和并发重试，仅产生一份任务与一轮发信 |
| R-03 | 多实例部署时，每日日期认领、任务领取、全局活动任务上限、发信轮换及节流具有跨实例一致性 | 两个实例同时触发同一天计划，只创建一份自动任务；工作进程不会重复发信 |
| R-04 | 停用、删除、平台变化、取消与进行中的读取/发信有明确竞争处理；最终返回结果前复核关键权限，旧操作不能覆盖终态 | 人为阻塞上游后变更策略或停止任务，释放请求后无串信、重复统计或任务复活 |
| R-05 | 导出具有完成性保证；中途失败必须向用户报告失败，不能把截断文件显示为完整成功 | 导出中制造存储/网络异常，页面不提示成功；重试结果数量正确 |
| R-06 | 关键操作留审计记录：生成/导出/启停卡密、变更/删除链接、创建/停止/复检任务、修改发件配置、启停/撤销节点 | 可查操作者、时间、动作、对象、数量及结果，不记录完整卡密、邮箱/SMTP/节点凭据 |
| R-07 | 请求限流与容量限制在多实例下仍有效；部署需明确可信代理与真实来源识别，默认不信任客户端伪造头 | 更换实例不能绕过兑换限流，伪造转发头不能绕过限制或改写节点 IP |
| R-08 | 密钥与受保护数据可备份、恢复和受控换密；恢复后旧卡密和链接仍可使用，备份不暴露凭据 | 在隔离环境恢复备份并验证卡密、链接、策略、任务历史及节点访问边界 |
| R-09 | 任务历史、报告、事件、临时快照有容量监测与清理策略，清理不能破坏在用游标、来源关系和审计追溯 | 达到容量阈值给出可观测提示；过旧增量改用快照，不造成静默丢失 |
| R-10 | 公共 URL 兼容与权限语义形成回归用例；任何新路径、缓存或适配器都复用相同策略校验 | 同一链接从新旧入口读取结果一致，过期/停用在各入口都受限 |
| R-11 | 卡密精确搜索保留，但通过受保护请求体提交，禁止完整卡密进入查询参数；网关、服务端日志及监测统一脱敏 | 搜索结果正确，地址栏/请求 URL/访问日志不出现完整卡密 |
| R-12 | 有路径前缀的部署按全流程适配，包括页面接口请求、列表翻页、复制、导出、兑换及报告下载 | 在实际前缀代理下完成四模块关键操作，不误请求站点根目录或生成错误地址 |

R-03 不能简单依赖单进程锁；R-02 的任务创建幂等与现有“结果写入幂等”是不同要求。若新项目第一版仅部署单实例，也应明确限制并避免宣称已支持多实例安全执行。

### 9.1 性能与容量验收口径

- 按模块保留本文明确的数量、请求体、并发、超时和分页限制；越界返回可理解错误，不能拖垮进程或静默截断。
- 现有读取基准为每节点上游并发默认 16，可配置 1～128，同账号操作串行；相同读取请求合并，正常短缓存 8 秒，上游许可等待约 3 秒超限返回繁忙。
- 缓存、公共分页会话和任务队列必须有容量上限。实现可调整内部结构，不能无限缓存邮件正文、游标或失败详情。
- 建议新项目采用原项目规模作为验收目标：1000 主邮箱、100000 链接、4 个子节点完整同步；在正常 8 秒缓存和 5 秒同步周期下，200 并发公共读取持续 10 分钟，P95 小于 1 秒、错误率小于 1%。
- 上述吞吐目标是模拟邮件服务环境中的目标，不是本次已执行的测试结果，也不能作为真实邮箱冷缓存延迟保证。真实服务商的授权、限流、网络和邮件特性需另做小规模联调与容量评估。
- 需覆盖大量链接筛选/导出、同邮箱并发请求、子节点重新快照和验证任务同时执行；不能只测试空数据库首页。
- 可观测指标至少覆盖任务积压、任务失败/待确认、上游超时、SMTP 发送及限流、节点同步延迟、快照失败和公开接口错误率；指标不得使用完整敏感凭据作为标签。

### 10.2 迁移模式与默认口径

默认将“移植功能”作为必须范围。是否迁移旧数据不阻塞需求设计，按以下两种模式准备：

- **空数据新项目**：实现完整功能，使用新 ID、卡密和节点凭据；不声称旧链接或旧卡密可用。
- **承接既有业务**：保留卡密内容、链接解析能力、身份映射、策略和历史；旧域名需继续路由到新系统或提供保持原路径与查询的兼容转发。

承接已有业务时，管理接口可重设计，已交付公共 URL 和卡密属于外部契约，不得随内部模型变化静默失效。

### 10.3 需要迁移的数据

| 数据 | 至少保留 | 注意事项 |
| --- | --- | --- |
| 主邮箱 | ID 映射、地址、类型、启停、公开标识、取信必需配置 | 内部 ID 可映射，公开标识及关系必须稳定 |
| 平台 | ID、名称、发件规则、关键词、版本映射 | URL 中的旧平台 ID 须可解析 |
| 链接 | ID 映射、完整收件人、主邮箱/平台绑定、期限、创建时间、旧 Token 校验能力 | 不重置有效期；不能只迁移短地址字符串 |
| 卡密 | 原卡密、主邮箱绑定、启用、生成/首次兑换时间、摘要校验能力 | 不重新随机生成；管理 TXT 不含关系与状态 |
| 验证对象 | 来源映射、父子关系、检测分组、模式/修订和策略关系 | 不把旧销售状态强行带入新模型 |
| 任务历史 | 主子邮箱快照、结果/说明、标识、发送信息、原任务关系 | 旧标识用于复检；迁移不重放发信 |
| SMTP | 默认配置、发件池、加密授权码、启停、轮换必要状态 | 受控解密后再加密，或保留兼容解密能力 |
| 每日计划 | 配置、时区关联、上次认领日期/任务/错误 | 迁移切换期避免新旧系统重复自动发信 |
| 节点 | 状态、游标、受保护凭据或受控换凭据方案 | 若换同步协议/数据代际，强制安全全量初始化 |
| 统计与审计 | 链接映射、各节点本地计数及历史审计 | 不能把主节点本地计数冒充全节点总量 |
| 密钥元数据 | 对应版本、解密能力、恢复说明 | 数据库与配套密钥须能一起恢复；不写进公开文件 |

现有链接导出 `子邮箱----URL`、卡密导出“一行一卡”、兑换结果导出都不是完整备份。不得仅靠这些文件宣称已完成数据迁移。

### 10.4 迁移执行顺序

1. 固定迁移口径和映射规则，在隔离环境演练；统计各类对象数量、关系和状态。
2. 制作一致备份，保存对应密钥恢复能力。停用或协调新旧系统的定时发信，处理正在执行任务，避免双写与重复投递。
3. 依次导入共用设置/主邮箱、平台、链接，再导入卡密、验证来源/历史、SMTP 和计划；最后处理节点。
4. 敏感数据通过受控迁移入口转换加密，不能通过普通日志、浏览器下载或公共兑换接口搬运。
5. 校验唯一性、父子关系、到期时间、卡密原值/状态/首次兑换时间、旧 URL 解析、来源策略及历史可追溯性。
6. 子节点采用兼容同步或新凭据重新初始化，在完整追平前保持未就绪。不能把旧协议游标直接当成新协议游标。
7. 切换域名或入口后执行公开链接、兑换、验证及节点联动验收；确认仅一个系统承担自动计划。
8. 保留可恢复的旧系统快照和切换记录，明确回退后如何处理新产生的卡密兑换状态、任务及配置变更，避免直接覆盖导致丢失。

迁移程序应支持校验预览和重复执行。重复执行不得新增第二张卡、重新计算原到期时间或重复创建来源映射。
